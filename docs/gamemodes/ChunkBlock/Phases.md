# 魔法方块和阶段

ChunkBlock 的魔法方块是 AOneBlock 引擎，故意不变地进行。关于阶段文件的所有事物——加权方块和生物群落、`fixedBlocks`、全息图、箱子和稀有性、自定义方块、版本管制、开始和结束命令、需求、阶段索引——完全按照它在 AOneBlock 中的方式工作，文件格式是相同的。

这意味着：

- **社区阶段包逐字工作。** 为 AOneBlock 编写的阶段文件放入 ChunkBlock 的 `phases` 文件夹并运行。
- **你可以在你自己的 AOneBlock 阶段复制过来** 无需编辑。
- **来自上游的修复和特性也到达这里**，因为引擎保持在步调而不是分叉。

!!! abstract "完整字段参考：[自定义 AOneBlock 阶段](../AOneBlock/Phases.md)"
    那份指南是完整的演练——每个数字的含义、加权抽奖如何用工作示例、箱子、自定义方块、版本管制和如何从零开始建造一个阶段。所有应用于这里完全不变。

    只有 **命令名** 不同：在整个过程中将 `/oba` 读作 `/chadmin`，将 `/ob` 读作 `/ch`。

这个页面涵盖 ChunkBlock 特有的内容。

## 文件在哪里

```
plugins/BentoBox/addons/ChunkBlock/
├── config.yml
├── phases_index.yml          ← 顺序、长度、启用、版本管制
├── panels/
│   └── phases_panel.yml      ← `/ch phases` GUI 模板
└── phases/
    ├── 0_plains.yml          ← 方块、生物、全息图、命令
    ├── 0_plains_chests.yml   ← 那个阶段的战利品
    ├── 700_underground.yml
    └── …
```

`phases/` 中的文件在升级时 **永不被覆盖**，所以你的编辑存活。船运于更高版本的新阶段通过协调自动恢复到索引。

## 阶段索引

`phases_index.yml` 是关于哪些阶段加载、以什么顺序、每个有多长、以及各自需要哪个 Minecraft 版本的真实来源。它被 **在** 任何阶段文件被解析之前读取，所以需要一个更新 Minecraft 版本的阶段被跳过，没有它的 YAML——或它里面的任何物品——被触及。

每个条目采用这些字段：

| 字段 | 含义 |
|---|---|
| `file` | `phases` 文件夹中阶段文件的基础名称，没有 `.yml`。箱子文件是 `<file>_chests.yml`。 |
| `section` | 阶段文件内的顶层键（历史上是开始方块）。 |
| `name` | 显示名称，在日志和在 `/chadmin phases` 面板中使用。 |
| `length` | 阶段中的方块数。 |
| `enabled` | 可选的，默认为 `true`。设为 `false` 以排除一个阶段。 |
| `requiredMinecraftVersion` | 可选的。在比这个版本更旧的服务器上，阶段被跳过——占用零方块。 |

开始方块是 **计算的**：上方启用的阶段长度的运行总和，从 0 开始。阶段可以自由重新排序，被跳过的阶段从进度中收起。

当你第一次在面板中编辑一个长度时，顶层 `adminLengths: true` 被自动写入。从那以后协调永远不会重新计算长度，所以你的值通过后来的文件添加、重命名和升级存活。

### 协调

索引被协调反对磁盘上实际存在的文件在每次加载和在管理面板的每次保存，所以什么 `/chadmin phases` 显示是什么你的服务器真正运行。看启动日志以 `Phase index:` 开头的行——它们说准确什么改变了。

- 一个条目其文件被 **在附属插件版本之间重命名** 被重新指向你的文件按阶段名称。
- 一个条目其文件是 **缺失但船运于 jar** 被自动恢复。这是如何新阶段出现在升级的服务器上，给予 `phases/` 永不被覆盖。
- **自定义阶段文件** 放入文件夹被自动添加。一个数字键插槽在它的遗留开始方块；其他被追加到结束供你在面板中排列。
- 文件永远消失的条目被移除，带一个警告。

!!! warning "删除一个阶段"
    要永久移除一个阶段，删除它的文件，或在 `/chadmin phases` 中切换它关闭。只删除索引条目不工作——协调重新添加任何它在文件夹中找到的阶段文件。

    一个格式错误的索引回退到直接文件加载，所以一个坏编辑不能留下附属插件卡住。

!!! tip "文件名中的数字是可选的"
    一个自定义 `desert.yml` 带有一个 `desert:` 部分工作很好。箱子文件按文件名仍然配对（`<file>_chests.yml`）。船运文件中的数字是历史的：与索引掌管，面板的开始和长度值是真的。

## 阶段顺序编辑器

`/chadmin phases`（权限 `chunkblock.admin.phases`，OP 默认）显示每个阶段按顺序有它的计算开始方块、长度和状态。它编辑 `phases_index.yml`，并删除和切换保存索引和立即重新加载阶段。

- **左键单击** 一个阶段来拿起它——其他人缩小左边。点击它应该去或使用放在结束插槽来推其他右边和掉落，或点击其他地方或关闭面板来不保存就放它回去。
- **右键单击** 切换一个阶段打开或关闭。
- **Shift-左键单击** 设置一个阶段的长度。面板关闭和聊天提示显示当前长度；输入一个整数数字来应用它，或 `cancel` 来保存它。无效输入重新提示，提示在 60 秒后超时。第一次长度编辑写 `adminLengths: true` 到索引。

禁用的阶段显示为灰色玻璃，版本锁定的为屏障——两者仍然可以被重新排序。一个没有配置图标的阶段使用它的第一个方块。

## 玩家和阶段

- `/ch count` ——当前方块数和阶段，在聊天中。
- `/ch phases` ——阶段 GUI。需要 `chunkblock.phases`，默认 **关闭**。
- `/ch setcount <number>` ——重放一个已经到达的阶段。需要 `chunkblock.island.setcount`（OP 默认）并遵守 `set-count-cooldown` 配置值，默认 5 分钟。
- `/ch check` ——如果魔法方块消失，重生它或显示其粒子使你可以找到它。
- `/ch bossbar` / `/ch actionbar` ——切换进度显示，如果 `bossbar` / `actionbar` 在 `config.yml` 中启用。

全息图在魔法方块上方默认打开（`world.holograms: true`），使用原生 Minecraft 文本实体，并在 `hologram-duration` 秒后消失。

## 管理阶段工具

- `/chadmin setcount <player> <number> [lifetime]` ——设置玩家的方块数，或他们的终身数。
- `/chadmin setchest <phase> <rarity>` ——简单的方式来建造战利品。填充一个箱子游戏中你想要什么，看着它，并运行命令带阶段名称和 `COMMON`、`UNCOMMON`、`RARE` 或 `EPIC` 的稀有性。箱子被写入那个阶段的箱子文件，准备使用。删除箱子仍然意味着编辑文件和重新加载。
- `/chadmin sanity [<phase>]` ——报告阶段概率到控制台，所以你可以看你的权重实际加起来是什么。
- `/chadmin phases` ——上面描述的顺序编辑器。

## ChunkBlock 特定注释

!!! warning "魔法方块在中心区块，总是"
    中心区块永远不能被锁定，所以魔法方块总是可到达的。这是由数据模型保证的而不是通过检查：声称列表总是从中心区块开始，重新锁定永不能移除它。

!!! note "生物生成方块清理尊重边界"
    `mobs-clear-blocks: true` 让生成生物破坏方块来腾出空间——一个从 AOneBlock 进行的欺骗预防，所以玩家不能把魔法方块装在盒子中和窒息一切。被锁定的区块永不被修改，所以这只是影响你自己的领地。

!!! tip "阶段和领地互相拉"
    方块魔法方块产生提升岛屿等级，岛屿等级购买区块——所以一个慷慨的阶段也是一个快速扩张的阶段。如果扩张在你的服务器上感觉太快，提高 `levels-per-chunk` 通常是一个比重新平衡阶段权重更好的杠杆。

!!! note "下界和末地阶段仍然运行"
    下界和末地阶段是进度的一部分不管下界和末地 *世界* 是否被生成（两者默认关闭）。它们通过主世界魔法方块提供下界和末地方块和生物。
